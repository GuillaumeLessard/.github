# Contributing to QECTOR

Thank you for helping. This guide covers every QECTOR repository that does not have its own CONTRIBUTING file. [qector-decoder](https://github.com/GuillaumeLessard/qector-decoder/blob/main/CONTRIBUTING.md) has its own guide, with build steps: follow that one there.

## Useful contributions

- Reproduction reports from a clean clone, with your platform, versions and the exact commands you ran
- Bug reports with the smallest example that shows the problem
- Corrections to papers, proofs, datasets and documentation
- Benchmark results with the environment and the SHA-256 hashes of the files you used
- Installation feedback for Windows, Linux and macOS

Please do not send:

- Large rewrites without discussing them in an issue first
- Performance claims without the data to reproduce them
- Public exploit details for a security problem: report it privately, as the [security policy](https://github.com/GuillaumeLessard/.github/blob/main/SECURITY.md) explains
- Changes that remove licence notices or alter commercial rights

## How to contribute

1. For anything larger than a small fix, open an issue first so we can agree on the approach.
2. Fork the repository and make your change on a branch.
3. Keep each pull request to one topic, and say how you tested it.
4. Keep results checkable: if a change affects a number, a proof or a dataset, include what someone needs to reproduce it.
